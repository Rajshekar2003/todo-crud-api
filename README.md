# Todo CRUD API

A backend REST API for managing a to-do list, built with FastAPI and PostgreSQL, with Supabase Auth securing user accounts and protected routes, and an LLM-backed enrichment endpoint.

Built as part of the FlyRank Backend Track internship, across several assignments:
- A1 - Core CRUD API (in-memory storage)
- A2 - Storage moved to SQLite
- A3 - Storage moved to PostgreSQL, running in Docker via `docker compose`
- A4 - Authentication added with Supabase Auth: sign up, log in, log out, JWT verification, protected routes, and Swagger bearer-auth docs
- A17 - An LLM-backed /enrich endpoint added: takes a scraped book record, returns a category, summary, and quality flags, with schema validation, retries, cost logging, and a kill switch

## Tech stack

- Language / framework: Python 3, FastAPI
- Database: PostgreSQL (via Docker)
- Identity Provider: Supabase Auth
- LLM provider: OpenRouter (free tier)
- API docs: Swagger UI (auto-generated by FastAPI)

## Setup

### 1. Clone the repo

```bash
git clone https://github.com/Rajshekar2003/todo-crud-api.git
cd todo-crud-api
```

### 2. Create a virtual environment and install dependencies

```bash
python -m venv venv
venv\Scripts\Activate.ps1      # Windows PowerShell
pip install -r requirements.txt
```

### 3. Set up environment variables

Copy .env.example to .env and fill in your own values:

```bash
copy .env.example .env
```
DATABASE_URL=postgres://postgres:dev@localhost:5432/tasks
SUPABASE_URL=your_supabase_project_url
SUPABASE_KEY=your_supabase_anon_key
PORT=8000
LLM_BASE_URL=your_llm_base_url
LLM_API_KEY=your_llm_api_key
LLM_MODEL=your_llm_model

- SUPABASE_URL and SUPABASE_KEY come from your own Supabase project: Project Settings -> API. Use the anon / publishable key - never the service_role key.
- In your Supabase dashboard, under Authentication -> Sign In / Providers -> Email, turn off "Confirm email" so freshly signed-up test accounts can log in immediately.
- LLM_BASE_URL, LLM_API_KEY, LLM_MODEL come from OpenRouter (openrouter.ai) - sign up, turn on both privacy toggles at Settings -> Privacy (or free models return 404), create a key. Use LLM_BASE_URL=https://openrouter.ai/api/v1 and LLM_MODEL=openrouter/free.

### 4. Start the database

```bash
docker compose up -d db
```

### 5. Run the API

```bash
uvicorn main:app --reload --port 8000
```

The API will be available at http://localhost:8000, and interactive Swagger docs at http://localhost:8000/docs.

To develop the /enrich endpoint without spending any LLM calls, set LLM_STUB=1 before starting the server - it returns a fixed, schema-valid fake answer instead of calling the model.

## API reference

| Method | Route | Description | Auth required |
|---|---|---|---|
| POST | /auth/signup | Create a new user account | No |
| POST | /auth/login | Log in, returns an access token | No |
| POST | /auth/logout | End the current session | Yes (Bearer token) |
| GET | /public/info | Public, open info | No |
| GET | /protected/profile | Returns the logged-in user's profile | Yes (Bearer token) |
| GET | /protected/dashboard | Example second protected route (reuses the same auth guard) | Yes (Bearer token) |
| GET | /tasks | List all tasks | No |
| GET | /tasks/{task_id} | Get a single task | No |
| POST | /tasks | Create a task | No |
| PUT | /tasks/{task_id} | Update a task | No |
| DELETE | /tasks/{task_id} | Delete a task | No |
| POST | /enrich | Enrich a book record with category, summary, quality flags (LLM-backed) | No |

## Authentication flow

1. POST /auth/signup and POST /auth/login talk to Supabase Auth - Supabase handles password hashing and issues a JWT access token.
2. Protected routes expect that token in the request header: Authorization: Bearer <token>.
3. A reusable FastAPI dependency (require_user) verifies the token against Supabase on every request to a protected route, and rejects missing, malformed, or invalid/expired tokens with 401.
4. Swagger UI (/docs) has a lock icon on every protected route - click Authorize, paste a token once, and test any protected route from the browser without manually setting headers.

## LLM enrichment endpoint (/enrich)

Full job card: see JOB-CARD.md.

What it does: takes a scraped book record (title, description, price, rating, availability) and returns a category from a fixed list, a one-sentence summary, and a list of quality flags - so downstream code can sort and filter books without a human reading every description.

Try it (stub mode - no model call, no cost):

```bash
# Windows PowerShell - write the body to a file first to avoid quoting issues
'{"title":"A Light in the Attic","description":"Poems and drawings","price_gbp":51.77,"rating_text":"Three","availability_text":"In stock"}' | Out-File -FilePath valid.json -Encoding utf8

curl.exe -i -X POST http://localhost:8000/enrich -H "Content-Type: application/json" --data-binary "@valid.json"
```

Expected response:
```json
{"category":"fiction","summary":"A stubbed summary standing in for a real model answer.","quality_flags":[],"confidence":0.42}
```

Deliberately broken request (missing required field):

```bash
'{"price_gbp":51.77,"rating_text":"Three","availability_text":"In stock"}' | Out-File -FilePath broken.json -Encoding utf8

curl.exe -i -X POST http://localhost:8000/enrich -H "Content-Type: application/json" --data-binary "@broken.json"
```

Expected response: 400 Bad Request naming the missing field.

## Status codes used

| Code | Meaning |
|---|---|
| 200 | Successful read / login / enrichment |
| 201 | Resource created (signup, task creation) |
| 204 | Successful delete / logout, no content returned |
| 400 | Missing or invalid input |
| 401 | Missing, malformed, invalid, or expired token |
| 404 | Resource not found |
